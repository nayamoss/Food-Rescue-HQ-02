# Build contract (single source of truth for parallel work)

Repo base: Express server `artifacts/api-server/server.js`, vanilla chat UI in `public/` (rescue-chat.js, styles.css, index.html), state saved to `data/state.json`. Routes are served at `/api/*` and `/food-rescue-hq/api/*` (prefix is stripped). Keep state atomic-write behaviour. Do not add a database. Never hardcode secrets: read env vars only.

## Journey (six steps)
1 add event, 2 agent questions fill event details, 3 photo of what is left, 4 agent matches places, 5 volunteers asked, 6 call (and text later) to coordinate. Summary at the end.

## State additions (all keys optional on old saved state; normalise on load)
```
event:   { id, name, venue, date, organizer, contact, goodForMinutes, items:[{item, ordered}], notes }
report:  { items:[{item, ordered, left, unit, source:"manual"|"photo"|"photo_edited", confidence?}], confirmedAt }
places:  [{ id, name, type:"shelter"|"kitchen"|"food bank", distanceMiles, capacity, accepts:["prepared","packaged","drinks"], address? }]
offers:  [{ id, placeId, volunteerId, item, portions, status:"proposed"|"offered"|"accepted"|"declined"|"picked_up"|"dropped_off", updatedAt }]
volunteers: [{ id, name, phone, optedIn, status:"ready"|"asked"|"accepted"|"declined"|"on_the_way"|"dropped_off" }]   (saved state)
```
Seed places: Partner shelter A (shelter, 2 mi, cap 150), Partner shelter B (shelter, 4 mi, cap 200), Community kitchen (kitchen, 6 mi, cap 100). Seed volunteers: Alex Rivera, Jordan Lee, Sam Taylor, with **no phone** (phone ""). There are no placeholder numbers; any old +1 202 555 xxxx number in saved state is dropped on load and rejected on input.
Users can add, edit and remove their own volunteers and places (endpoints below). New ids are generated by the server (`v-<uuid>`, `p-<uuid>`). A user who removes every place or a seed volunteer keeps it that way across restarts (no silent re-seeding).

### Phone masking
The browser never receives a full phone number. `snapshot()` (GET /api/state, GET /api/stream, the agent) replaces each volunteer's `phone` with:
```
volunteers: [{ id, name, optedIn, status, phoneSet: true|false, phoneLast4: "2671" | "" }]
```
The real number stays in `data/state.json`. Voice and SMS get it server side through the adapter in server.js: `getState()` is wired to `core.internalState()` (same shape as the snapshot, real phones) and `volunteerPhone(id)` to `core.volunteerPhone(id)`. Never return `internalState()` from an HTTP route. Phone numbers never appear in feed text, error messages or logs.
Feed entries: `{id, at, text, kind}`; system/HQ messages use kind "hq". Plain-language text only.

## Endpoints
| Method | Path | Body | Effect |
|---|---|---|---|
| POST | /api/event | {name, venue, date, items:[{item,ordered}], goodForMinutes?} | create or replace the event, clear old feed and offers |
| PATCH | /api/event | partial event fields | update details (used by agent questions) |
| POST | /api/report | {items:[{item,left,unit,source,confidence?}]} | confirm what is left, open the incident, compute proposed offers |
| POST | /api/offers/send | {offers?:[{id,portions}]} | adjust amounts, set status offered, assign volunteers, trigger calls if configured |
| POST | /api/offers/:id/respond | {action:"accept"\|"decline"} | update offer and volunteer status |
| POST | /api/offers/:id/pickup | {} | picked_up |
| POST | /api/offers/:id/dropoff | {} | dropped_off, update rescued totals |
| POST | /api/volunteers | {name, phone?, optedIn?} | add a volunteer (201). name 1-80 chars, unique; phone E.164 (spaces, dashes, brackets are stripped); optedIn defaults true |
| PATCH | /api/volunteers/:id | {name?, phone?, optedIn?} | edit; phone "" or null removes the number |
| DELETE | /api/volunteers/:id | | remove; 409 if they hold an offer that is offered, accepted or picked_up |
| POST | /api/volunteers/:id/phone | {phone} | set phone (E.164), never echoed in the feed |
| POST | /api/places | {name, type, distanceMiles, capacity, accepts, address?} | add a place (201). type shelter\|kitchen\|food bank; distanceMiles 0-1000; capacity whole number >= 1; accepts non-empty subset of prepared, packaged, drinks; name unique |
| PATCH | /api/places/:id | any of the place fields | edit (partial) |
| DELETE | /api/places/:id | | remove; 409 if it has any offer that is not proposed. Its proposed offers are dropped with it |
| POST | /api/estimate | {images:[dataUrl,...], items:[{item,ordered}]} | OpenAI vision estimate, returns {items:[{item,count,unit,confidence,note}], unreadable} |
| POST | /voice/offer | query volunteerId, offerId | TwiML: say the offer, Gather 1 accept / 2 decline |
| POST | /voice/answer | query volunteerId, offerId, form Digits | apply accept/decline, TwiML reply |
| GET | /v/:id | | volunteer page (static HTML that reads /api/state) |
| POST | /api/demo/reset | | clears event, report, offers, incident and feed. **Keeps** the user's volunteers (status back to ready, phones kept) and places |
| POST | /api/demo/reset-all | | full reset back to the seeded volunteers (no phones) and places |

Existing: GET /api/state, GET /api/stream, POST /api/updates, POST /api/demo/fast-forward.

All mutations save atomically and broadcast the new (masked) snapshot on /api/stream. Validation errors are 400 with a plain-language `{error}`; unknown ids are 404; rule conflicts (duplicate name, busy volunteer, place with sent offers) are 409.

`snapshot()` must include event, report, places, offers, volunteers, journeyStep ("event"|"details"|"photo"|"match"|"outreach"|"done"), summary {ordered, eaten, left, rescued, notRescued, byPlace[]}, plus existing totals.

## Env vars (add to .env.example, never commit values)
TWILIO_ACCOUNT_SID, TWILIO_AUTH_TOKEN, TWILIO_FROM_NUMBER, PUBLIC_BASE_URL, OPENAI_API_KEY, OPENAI_VISION_MODEL.
Optional: DATA_DIR (where state.json lives; default `<repo>/data`). The core self-test uses a temp DATA_DIR.

## Self-tests (no network)
`node artifacts/api-server/lib/<name>.selftest.mjs` for core, voice, sms, agent, estimate.
Missing credentials must never crash the app: skip the call or estimate and say so in plain language.

## File ownership (avoid conflicts)
- core data/matching/offers: `artifacts/api-server/lib/core.js` + minimal wiring lines in server.js
- voice: `artifacts/api-server/lib/voice.js`
- estimate: `artifacts/api-server/lib/estimate.js`
- frontend: files in `public/` only
