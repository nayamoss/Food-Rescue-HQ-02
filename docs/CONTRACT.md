# Build contract (single source of truth for parallel work)

Repo base: Express server `artifacts/api-server/server.js`, vanilla chat UI in `public/` (rescue-chat.js, styles.css, index.html), state saved to `data/state.json`. Routes are served at `/api/*` and `/food-rescue-hq/api/*` (prefix is stripped). Keep state atomic-write behaviour. Do not add a database. Never hardcode secrets: read env vars only.

## Journey (six steps)
1 add event, 2 agent questions fill event details, 3 photo of what is left, 4 agent matches places, 5 places called (stage 1), 6 a volunteer is called to carry it (stage 2) and confirms delivery. Summary at the end. Voice calls only; no SMS in this flow.

## Two-stage outreach (voice)
1. Admin confirms what is left (POST /api/report or POST /api/quick). Each leftover item becomes one **lot**. Every place that takes that kind of food is proposed for the lot, nearest first (places that can hold the whole lot are preferred; if none can, every place that takes it is proposed for as much as it holds).
2. **Stage 1, nonprofits.** POST /api/outreach/places (also /api/offers/send and /api/quick) calls every proposed place **with a phone** at once: "Food rescue. {qty} {items} available at {venue}, pickup within {minutes} minutes. Press 1 if you can take it, 2 if not." Places without a phone are marked `skipped`. The first place to press 1 wins the lot; the other places still being called become `taken` and are not called again (a call still ringing hears "Thanks, this has already been claimed"). Press 2 marks that place `declined`. If every place says no, or nobody says yes within 10 minutes, the lot is `unclaimed` and a plain HQ feed line says so. A lot with no place that has a phone is unclaimed straight away.
3. **Stage 2, volunteers.** As soon as a place says yes, the first free, opted-in volunteer **with a phone** is called: "Food rescue pickup. Pick up {qty} {items} at {venue} and drop off at {placeName}, {placeAddress}. Press 1 to accept, 2 to decline." Decline hands it to the next free volunteer with a phone (never back to someone who declined it). If nobody is free the lot waits; it is offered again when a volunteer is added, gets a phone, or finishes a delivery.
4. **Delivery confirmation.** After accepting, the call says "When you have dropped it off, call this number back or open your link and tap Delivered." The volunteer confirms with POST /api/offers/:id/delivered (volunteer page) or by calling the Twilio number (POST /voice/inbound), which reads their open job and says "Press 1 if you have delivered it". **Only a delivered confirmation counts as rescued.** The rescue is done when every lot is delivered or unclaimed: incident `resolved` if everything was delivered, otherwise `expired` with "Rescue finished: X of Y portions delivered."

## State additions (all keys optional on old saved state; normalise on load)
```
event:   { id, name, venue, date, organizer, contact, goodForMinutes, items:[{item, ordered}], notes }
report:  { items:[{item, ordered, left, unit, source:"manual"|"photo"|"photo_edited", confidence?}], confirmedAt }
places:  [{ id, name, type:"shelter"|"kitchen"|"food bank", distanceMiles, capacity, accepts:["prepared","packaged","drinks"], address?, phone }]   (saved state)
lots:    [{ id, item, unit, portions, kind, status:"proposed"|"calling_places"|"placed"|"unclaimed"|"delivered", placeDeadline, offerId, updatedAt }]   (saved state; snapshot shape below)
offers:  [{ id, lotId, placeId, volunteerId, item, portions, status, declinedBy?:[volunteerId], updatedAt }]
         stage 1 (place):     "proposed" -> "calling" -> "place_accepted" | "declined" | "taken" | "unclaimed" | "skipped" (place has no phone)
         stage 2 (volunteer): "place_accepted" (no volunteer yet) -> "offered" (volunteer asked) -> "accepted" -> "picked_up" -> "dropped_off" (delivered)
         Offers saved before lots existed have no lotId and keep the old behaviour.
volunteers: [{ id, name, phone, optedIn, status:"ready"|"asked"|"accepted"|"declined"|"on_the_way"|"dropped_off" }]   (saved state)
```
Seed places: Partner shelter A (shelter, 2 mi, cap 150), Partner shelter B (shelter, 4 mi, cap 200), Community kitchen (kitchen, 6 mi, cap 100). Seed volunteers: Alex Rivera, Jordan Lee, Sam Taylor, with **no phone** (phone ""). There are no placeholder numbers; any old +1 202 555 xxxx number in saved state is dropped on load and rejected on input.
Users can add, edit and remove their own volunteers and places (endpoints below). New ids are generated by the server (`v-<uuid>`, `p-<uuid>`). A user who removes every place or a seed volunteer keeps it that way across restarts (no silent re-seeding).

### Phone masking
The browser never receives a full phone number. `snapshot()` (GET /api/state, GET /api/stream, the agent) replaces each volunteer's and each place's `phone` with:
```
volunteers: [{ id, name, optedIn, status, phoneSet: true|false, phoneLast4: "2671" | "" }]
places:     [{ id, name, type, distanceMiles, capacity, accepts, address, phoneSet: true|false, phoneLast4: "0142" | "" }]
```
Place phones follow the volunteer rules: E.164, US numbers typed without +1 (7622357374, (762) 235-7374) are normalised to +1, placeholders rejected, `""`/`null` removes it. The real number stays in `data/state.json`. Voice and SMS get it server side through the adapter in server.js: `getState()` is wired to `core.internalState()` (same shape as the snapshot, real phones), plus `volunteerPhone(id)`, `placePhone(id)`, `callTarget(offerId)` (who to dial now) and `openJobForPhone(from)` (inbound caller lookup). Never return `internalState()` from an HTTP route. Phone numbers never appear in feed text, error messages or logs.
Feed entries: `{id, at, text, kind}`; system/HQ messages use kind "hq". Plain-language text only.

## Endpoints
| Method | Path | Body | Effect |
|---|---|---|---|
| POST | /api/event | {name, venue, date, items:[{item,ordered}], goodForMinutes?} | create or replace the event, clear old feed and offers |
| PATCH | /api/event | partial event fields | update details (used by agent questions) |
| POST | /api/report | {items:[{item,left,unit,source,confidence?}]} | confirm what is left, open the incident, compute proposed offers |
| POST | /api/outreach/places | {offers?:[{id,portions}]} | **stage 1**: adjust proposed amounts, call every proposed place with a phone (10 minute window). 409 if nothing is left to send |
| POST | /api/offers/send | same | older name for /api/outreach/places |
| POST | /api/quick | {text} | one sentence -> event, report, lots, then starts stage 1 (no longer calls volunteers directly) |
| POST | /api/offers/:id/respond | {action:"accept"\|"decline"} | whoever is being asked now: a place (status calling; first yes wins, 409 if already taken) or the volunteer (status offered; decline goes to the next free volunteer) |
| POST | /api/offers/:id/pickup | {} | picked_up (optional step) |
| POST | /api/offers/:id/delivered | {} | the volunteer confirms the drop-off: dropped_off, lot delivered, counts as rescued. 409 unless accepted or picked_up |
| POST | /api/offers/:id/dropoff | {} | older name for /delivered |
| POST | /api/offers/:id/call | {} | call now: the place while it is `calling`, the volunteer while `offered`/`accepted`/`picked_up`. 409 "Calls are not set up yet." without Twilio env; 409 if no phone or nobody to call |
| POST | /api/volunteers | {name, phone?, optedIn?} | add a volunteer (201). name 1-80 chars, unique; phone E.164 (spaces, dashes, brackets are stripped); optedIn defaults true |
| PATCH | /api/volunteers/:id | {name?, phone?, optedIn?} | edit; phone "" or null removes the number |
| DELETE | /api/volunteers/:id | | remove; 409 if they hold an offer that is offered, accepted or picked_up |
| POST | /api/volunteers/:id/phone | {phone} | set phone (E.164), never echoed in the feed |
| POST | /api/places | {name, type, distanceMiles, capacity, accepts, address?, phone?} | add a place (201). type shelter\|kitchen\|food bank; distanceMiles 0-1000; capacity whole number >= 1; accepts non-empty subset of prepared, packaged, drinks; name unique; phone as for volunteers |
| PATCH | /api/places/:id | any of the place fields | edit (partial); phone "" or null removes the number |
| DELETE | /api/places/:id | | remove; 409 if it has any offer that is not proposed. Its proposed offers are dropped with it |
| POST | /api/estimate | {images:[dataUrl,...], items:[{item,ordered}]} | OpenAI vision estimate, returns {items:[{item,count,unit,confidence,note}], unreadable} |
| POST | /voice/offer | query offerId + placeId (stage 1) or volunteerId (stage 2) | TwiML: the place or volunteer script, Gather 1 / 2. A taken place offer hears "already been claimed"; an accepted volunteer hears their job and can press 1 for delivered |
| POST | /voice/answer | same query, form Digits | place: first yes wins, a late yes hears "Thanks, this has already been claimed", 2 declines. Volunteer: accept (with the call-back instruction) or decline |
| POST | /voice/inbound | form From | the Twilio number's incoming-call webhook. A known volunteer with an open job hears it and "Press 1 if you have delivered it" |
| POST | /voice/delivered | query offerId, volunteerId, form Digits | 1 marks the job delivered (only for the volunteer holding it) |
| GET | /v/:id | | volunteer page (static HTML that reads /api/state) |
| POST | /api/demo/reset | | clears event, report, offers, incident and feed. **Keeps** the user's volunteers (status back to ready, phones kept) and places |
| POST | /api/demo/reset-all | | full reset back to the seeded volunteers (no phones) and places |

Existing: GET /api/state, GET /api/stream, POST /api/updates, POST /api/demo/fast-forward.

All mutations save atomically and broadcast the new (masked) snapshot on /api/stream. Validation errors are 400 with a plain-language `{error}`; unknown ids are 404; rule conflicts (duplicate name, busy volunteer, place with sent offers) are 409.

`snapshot()` must include event, report, places, lots, offers, volunteers, journeyStep ("event"|"details"|"photo"|"match"|"outreach"|"done"), summary {ordered, eaten, left, rescued, notRescued, byPlace[]}, plus existing totals.

### Snapshot `lots` (what the UI shows per lot)
```
lots: [{
  id, item, unit, portions, kind: "prepared"|"packaged"|"drinks",
  status: "proposed" | "calling_places" | "unclaimed" | "waiting_volunteer" | "calling_volunteer" | "on_the_way" | "delivered",
  stage:  "match" | "places" | "volunteer" | "done",
  label:  "Ready to call nonprofits" | "Calling nonprofits" | "Nobody took it"
        | "Partner shelter A said yes. Waiting for a free volunteer" | "Partner shelter A said yes. Calling Jordan Lee"
        | "Jordan Lee is on the way" | "Delivered to Partner shelter A",
  steps: [   // always these five, in order. state: "done" | "active" | "waiting" | "failed" | "todo"
    { key: "places",     label: "Calling nonprofits",         state },   // "failed" when the lot is unclaimed
    { key: "place_yes",  label: "Partner shelter A said yes", state },   // "A place says yes" until one does
    { key: "volunteer",  label: "Calling Jordan Lee",         state },   // "Calling a volunteer" until one is asked; "waiting" if nobody is free
    { key: "on_the_way", label: "On the way",                 state },
    { key: "delivered",  label: "Delivered",                  state },
  ],
  placeDeadline: ISO | null,   // end of the 10 minute stage 1 window
  offerId, placeId, placeName, placeAddress, volunteerId, volunteerName,   // the winning offer; null / "" until a place says yes
  places: [{ offerId, placeId, name, portions, phoneSet, status: "proposed"|"calling"|"accepted"|"declined"|"taken"|"unclaimed"|"skipped" }],
  updatedAt,
}]
```
`journeyStep` is "match" while every lot is proposed, "outreach" while any lot is open, "done" when every lot is delivered or unclaimed. `summary.rescued`, `summary.byPlace[].rescued` and `totals.rescued` count delivered (dropped_off) portions only; `byPlace[].portions` counts lots a place said yes to.

## Env vars (add to .env.example, never commit values)
TWILIO_ACCOUNT_SID, TWILIO_AUTH_TOKEN, TWILIO_FROM_NUMBER, PUBLIC_BASE_URL, OPENAI_API_KEY, OPENAI_VISION_MODEL.
Optional: DATA_DIR (where state.json lives; default `<repo>/data`). The core and voice self-tests use a temp DATA_DIR.
Twilio setup: point the Twilio number's incoming-call webhook at `POST {PUBLIC_BASE_URL}/voice/inbound` so volunteers can call back to confirm delivery.

## Self-tests (no network)
`node artifacts/api-server/lib/<name>.selftest.mjs` for core, voice, sms, agent, estimate.
Missing credentials must never crash the app: skip the call or estimate and say so in plain language. The voice self-test stubs `fetch` and never reaches Twilio. The stage 1 window is injectable for tests: `core.setPlaceTimeoutMs(ms)` and `core.checkTimeouts(now)`.
